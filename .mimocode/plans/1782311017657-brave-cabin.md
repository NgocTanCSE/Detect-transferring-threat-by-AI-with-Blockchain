# Fix: Frontend proxy + Scanner DNS errors on HF

## Problem 1: Frontend proxy to wrong backend
Login fails with "Internal Server Error" because Next.js rewrites proxy `/api/*` to `http://api-gateway:8001` which doesn't exist on HF.

**Root cause**: `next.config.mjs` defaults `BACKEND_URL` to `http://api-gateway:8001`. This is baked at build time in Stage 1, but Stage 1 has no `BACKEND_URL` env var.

**Fix**: Set `BACKEND_URL=http://127.0.0.1:8000` as ENV in Dockerfile Stage 1 before `npm run build`.

### File: `Dockerfile` (Stage 1)
Add before `RUN npm run build`:
```dockerfile
ENV BACKEND_URL=http://127.0.0.1:8000
```

## Problem 2: Scanner tries to call microservices that don't exist on HF
Scanner errors: `analytics-service` and `alert-service` DNS failures. These services only exist in docker-compose, not in HF single-container mode.

**Fix**: Make scanner calls to external services graceful with try/except and no retry. Or add fallback URLs that point to localhost.

### File: `backend/scanner.py`
Find where it calls `analytics-service:3005` and `alert-service:3003`, change to `127.0.0.1:8000` or wrap in try/except with silent failure.

2. `backend/scanner.py` - Fix service URLs for HF mode
